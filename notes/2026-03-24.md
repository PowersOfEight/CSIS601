#### The lost update problem
* The lost update problem
  - Occurs when two transactions that access the same db items have operations interleaved
  - Results in incorrect value of some db items

#### The temporary update problem

This problem occurs when one transaction updates a db item and then the transaction fails for some reason
Meanwhile, the updated item is accessed by another transaction before it is changed back

#### The incorrect summary problem

If one transaction is calulating an aggregate summary function on a number of db items while other transactions are updating some of these items the aggregate function may calculate some values before they are updated and some after

#### The unrepeatable read problem

Transaction `T` reads the same item twice
* Value is changed by another transaction $T^\prime$

### Transaction Schedule

* When transactions are executing concurrently in an interleaved fashion,
then the ordering of the operations from all the various transactions is known as a schedule (or history)
* A schedule (or history) $S$ of $n$ Transactions $T_1,T_2,\ldots,T_n$
We suppose that the combined set of operations $m =\ \mid \bigcup_{i=1}^{n} T_i \mid$
We consider this a sequence $\left(o_k\right)_{k \in [m]}$ to be the transaction


* Two operations in a schedule are said to **conflict** if they satisfy all three conditions


### Recoverable schedules
* A schedule is recoverable if
  * No transaction $T$ of $S$
